决定自己搭博客时，我第一个纠结的问题是：**要不要数据库。**

## 先问规模

一年能写多少篇？往多了算，一百篇。每篇平均 3000 字，总计 30 万字，不到 1 MB。

这个数据量下，数据库带来的东西（索引、事务、并发写）一项都用不上。而它带来的成本——一台要养的服务器、备份、升级、被扫描——全都是净支出。

## 文件即数据库

markdown 文件本身就是一条结构化记录，文件头的 frontmatter 就是字段：

```yaml
---
title: '为什么我把博客迁到了 Astro'
pubDate: 2026-09-28
draft: false
---
```

草稿箱不需要一张 `posts` 表加一个 `status` 字段——`draft: true` 就够了，构建时过滤掉。
合集不需要一张 `collections` 表和外键——一个目录就够了。

> 当你能用文件系统解决问题时，加数据库通常是在给自己找活干。

## 什么时候才真的需要

我把判断标准写成了一张表，后来每次想加功能都会回来对照：

| 需求 | 需要数据库吗 |
| --- | --- |
| 发文章、草稿、合集 | 不需要 |
| 站内搜索 | 不需要（构建时生成索引） |
| 评论 | 看情况（Giscus 挂 GitHub，零数据库） |
| 阅读数、点赞 | 需要动态写入，得有 |
| 多人协作登录 | 需要 |

## 结论

静态站点不是「退而求其次」，对个人博客来说它就是正解。文章躺在 Git 里，diff 就是修改历史，`git revert` 就是后悔药——这套东西数据库给不了。
