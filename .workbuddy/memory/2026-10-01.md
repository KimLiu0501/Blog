## 依赖安装大面积损坏的排查（16:10）

- 现象：`npm run dev` 报 `Cannot find module 'node_modules/html-escaper/esm/index.js'`。
- 排查：该包的 `esm/` 目录存在但为空 → 解包不完整。用 `find node_modules -maxdepth 3 -type d -empty` 扫了一遍，发现 20+ 个包目录为空（is-docker、zwitch、ms、base-64、@types/hast、@types/mdast、@types/estree、property-information 等），说明整次安装大面积损坏，不是个别包问题。
- 修复：删 `node_modules` + `package-lock.json`，`npm cache clean --force` 后重装。国内网络建议加 `--registry=https://registry.npmmirror.com`（或写进项目级 .npmrc）。
- 教训：遇到 `ERR_MODULE_NOT_FOUND` 且路径确实存在时，先查目录是不是空的——这是解包失败的典型特征，别去改 import 路径。

## 方案最终确定（21:45）

- 小k 问要不要用线上服务器，我给了判断后他决定**不买服务器**，维持 Cloudflare Pages + Sveltia CMS + GitHub OAuth、零数据库。
- 判断依据：静态站迁移成本≈0（dist 目录扔哪都能跑），所以基础设施决策可以延后；换 VPS 是净亏（要自建 Nginx/SSL/备份，境外 VPS 国内访问未必更快，国内服务器要备案）。只有「不依赖 GitHub 的后台」或「国内访问速度」成为真问题时才值得换。
- 加了 `public/_headers`：Cloudflare Pages 缓存策略——`/_astro/*` 长缓存（文件名带 hash）、`/images/*` 一周、全局 nosniff + referrer 策略。文章更新后能立刻生效。
- 页脚加了低调的「管理」入口指向 `/admin/`。
- 待办清单：部署 workers/oauth 拿 workers.dev 地址 → 注册 GitHub OAuth App（callback 填 worker 的 /callback，Homepage 先填 localhost）→ 填 config.yml 的 repo/branch/base_url → 买域名后改 astro.config.mjs 的 site。

## 部署踩坑：wrangler 登录（22:00）

- `npx wrangler deploy` 的浏览器 OAuth 登录失败，回调 `localhost:8976/oauth/callback` 打不开。**大概率是系统代理/VPN 把 localhost 也代理了**（国内环境常见）。
- 解决：不用浏览器登录，改用 API Token——Cloudflare 面板 My Profile → API Tokens → 用「Edit Cloudflare Workers」模板创建，然后 `export CLOUDFLARE_API_TOKEN=xxx` 再 deploy。若报缺 account_id 再 `export CLOUDFLARE_ACCOUNT_ID=xxx`。
- 已在 wrangler.toml 里注释写明这条路径和 account_id 的填写位置。
- 另一个首次部署的坑：Cloudflare 要求先激活 workers.dev 子域（Workers & Pages 面板里点一下），否则 deploy 会报 subdomain 未注册。
- `astro.config.mjs` 里的 `site` 要换成他买的境外域名。
- Cloudflare Pages：构建命令 `npm run build`，输出目录 `dist`，Node 版本环境变量设 22。
- `src/site.ts` 里的站名、简介、导航改成他自己的。
